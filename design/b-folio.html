Module 1, lesson 3

Reading a test, running it, reading a failure

35 minutes · beginner · after “venv and pip”

A test is a sentence of the specification: given this input, the result must be this. Read the three tests below as you would read requirements, and the bug becomes visible before you run anything.

When pytest reports assert 3 == 2, the left side is what your code produced and the right side is what the test expected. The line underneath, where 3 = count_words('go py'), names the call that produced it.

A green test is only as good as what it checks.

That's why every exercise in this academy ships the edge cases you skipped in your assessment: empty input, extra whitespace, ties.

From Gogo test wants func TestX(t *testing.T) and messages you write. pytest discovers test_* functions and explains failures itself.
